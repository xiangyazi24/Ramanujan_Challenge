## Fixed-q hit reconstruction

The reconstructed object is:

```
n = q*p + u
```

with

```
p | b_u
```

and paired index

```
ell = p-d,
h = q*d.
```

The second hit is checked through

```
ell | b_{u+h}
```

after translating the row coordinate. The implementation does not replace u+h by a wrapped residue; it uses the actual row value, which is required.

## Pair ordering

The correct canonical ordering is:

```
ell < p
```

with

```
d = p-ell,
h=q*d.
```

The audited code does not double count the same pair through the reversed representation.

## Alignment criterion

The deletion rule is:

```
aligned = cross1 OR cross2
```

where the two possible cross divisibilities correspond to the two directions of the reflection alignment. Using AND would retain invalid pairs; the audited implementation uses OR.

## Performance findings

The main scaling issue is not correctness but complexity.

The expensive operations are:

1. iterating candidate p values;
2. generating nearby prime partners ell=p-d;
3. checking pair alignment and recurrence data.

For large p_max the pair stage dominates. The binary bank parser is not the bottleneck.

Recommended engineering change (not theorem change): keep the current correctness path and add indexed lookup for prime pairs by residue gap and quotient cell.
