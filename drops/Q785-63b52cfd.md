## 1. The valid k=2 extraction from (4.4)--(4.5), (5.1)--(5.3)

Let

```
T_q(n) >= kappa n/log n
```

be the total number of target residues in the fixed-q window. For k=2 set

```
H = ceil(64 L/T_q(n))
```

where L is the available residue interval length. Since

```
H = O_q(log n),
```

we split the ordered target residues into adjacent windows of diameter H.

Delete:

1. pairs with gap larger than H;
2. all aligned pairs (same prime carrier or same quotient cell obstruction).

The remaining adjacent pairs have gaps

```
1 <= h <= H
```

and are fully transverse.

The adjacent-window pigeonhole gives

```
sum_{1<=h<=H} N_h(n) >= c_q T_q(n)^2/L - E_align - E_long,
```

where N_h counts transverse pairs of residue gap h.

Since H=O(log n), there exists a fixed

```
h in {1,...,H}
```

such that

```
N_h(n) >= (c_q/H) T_q(n)^2/L - (E_align+E_long)/H.
```

Under the intended normalization L=Theta(n) and T_q(n)>=kappa n/log n this becomes

```
N_h(n) >= c'_q n/(log^3 n)
```

provided the two error terms are negligible at that scale.

This is the actual consequence of the k=2 combinatorial step.

## 2. LGTQ-3 does not automatically imply LGTQ-2

The implication claimed in Q782 is invalid from projection alone.

A triple count has the form

```
M_3(h1,h2) <= M_2(h1),
```

but the required scales are different:

```
LGTQ-3: M_3 >> n/log^3 n,
LGTQ-2: M_2 >> n/log^2 n.
```

Projection loses a possible logarithmic factor because one pair may have only O(1/log n) successful extensions.

Therefore

```
LGTQ-3 => LGTQ-2
```

is not a formal consequence of the definitions.

## 3. Abstract counterexample: triple does not imply pair scale

Let the pair packet count be

```
P_n = n/log^2 n.
```

Suppose every pair packet has exactly

```
1/log n
```

fraction of possible extensions. Then

```
M_3 = P_n/log n = n/log^3 n,
```

while

```
M_2=P_n=n/log^2 n.
```

This example shows projection is compatible with the expected logarithmic loss. Conversely, if one only observes triples, there is no information forcing the pair count to exceed the weaker projected scale.

A second abstract array:

```
P_n=n/log^3 n,
M_3=n/log^3 n
```

shows that a triple lower bound at the n/log^3 scale can coexist with a pair count below the required n/log^2 scale.

Hence an extension multiplicity theorem is required.

## 4. What would prove a real implication

A genuine implication requires a uniform extension lower bound.

If for every LGTQ-2 pair

```
#extensions >= c log n
```

then

```
M_3 >= c log n M_2,
```

and a triple theorem at n/log^3 would imply a pair theorem at n/log^2.

But this extension multiplicity is exactly the missing arithmetic input. It is not supplied by the combinatorial pigeonhole argument.

## 5. Audit of O_q(1) aligned pairs

The statement

```
number of aligned pairs = O_q(1)
```

is too strong without an additional uniqueness argument.

The correct safe statement is:

```
number of aligned pairs is bounded by the number of solutions of the same-carrier congruence system.
```

For fixed q, this may be small, but proving O_q(1) requires showing the carrier equation has bounded multiplicity in the relevant interval.

The local congruence alone does not provide this.

## 6. Audit of long-gap contribution

The claim that all long gaps are negligible is also incomplete.

For gaps h>H, the trivial estimate is only

```
#pairs with h>H <= T_q(n)^2.
```

No saving follows unless there is an independent spacing estimate.

A valid argument needs one of:

* a dispersion estimate for target residues;
* a large-sieve bound for the residue process;
* a proven clustering bound.

Without such an input, deleting long gaps is an assumption, not a deduction.
