# P3.2 — exact globalization audit of `q32_cross_slope_gap_charge_scan.py`

## Verdict

There are **two different senses** of “uses a companion value beyond `p`,” and the script separates them cleanly.

1. **Actual unscaled companion evaluations:** all are in the first block `0 <= n <= p-1`. The script constructs only

```text
c_0, c_1, ..., c_(p-1)  (mod p)
```

and its helper `c_first_block(n)` explicitly throws an error if `n >= p`.

2. **The slope-4 transverse associated-graded column:** this does formally stand for values

```text
p^3 c_n
```

at physical indices `n >= p`, up to

```text
n = 2p-1-r,
```

but the script **never evaluates the rational number `c_n` there**. It immediately applies the exact seam law

```text
p^3 c_(p+q) ≡ b_q (mod p),   0 <= q < p,
```

and therefore computes the entire slope-4 transverse charge from ordinary first-block Apéry values `b_q`.

So the Q3527 auxiliary-denominator primes such as `167` and `211` **do not occur anywhere in the numerical `det_bc` scan**. In that limited but important sense, the scan has already avoided the literal reflected-companion globalization obstruction.

However, the next inference in the question is too strong:

> “The scan avoids high-index raw companion denominators” does **not** yet imply “the local `p`-unit determinant is one prime-independent global integer `E` of height `o(n)`.”

The script computes a **prime-dependent associated-graded residue**. Its slope-4 replacement `p^3 c_(p+q) -> b_q mod p` is a congruence in `Z_(p)`, not a characteristic-zero identity identifying all target primes with one fixed integer. One can make a denominator-free integral lift for each individual target `p`, but that lift still depends on `p` through the shift by `p`, the hit `R_4`, and the cutoff data. No theorem in the script identifies those different lifts with a single `E(m,H)` or proves `o(n)` height.

Thus the correct campaign update is:

```text
Q3527 literal auxiliary-companion denominator obstruction:
    AVOIDED by the scan at the local associated-graded level.

All raw c_n evaluations in the scan:
    n <= p-1.

Formal slope-4 p^3 c_n coordinates:
    some n > p, up to 2p-1-r.

Are those high-index rational c_n actually evaluated?
    NO; they are replaced immediately by b_(n-p) mod p.

Does det_bc itself numerically depend on any unscaled companion value?
    NO.

Does this already give the desired global prime-independent E?
    NO.  A prime-independent characteristic-zero lift + o(n)-height theorem is still missing.
```

The remaining globalization problem has changed form: it is no longer “clear auxiliary denominators of `c_(2p-1-r)`.” It is now “globalize the **piecewise first-seam associated-grade Apéry row** simultaneously for all target primes without reintroducing a target-prime product or linear height.”

# 1. Which companion evaluations does the script actually construct?

The only ordinary companion array is built by

```python
def unit_companion_first_block_mod_p(p: int) -> list[int]:
    """c_0=0,c_1=1, Lc=0 for n>=1, through index p-1 mod p."""
    c = [0] * p
    c[0] = 0
    c[1] = 1
    ...
```

Thus by construction the array contains exactly

```text
c[0], c[1], ..., c[p-1].
```

Inside `compute_record`, the wrapper is even stricter:

```python
def c_first_block(n: int) -> int:
    if not (0 <= n < p):
        raise ValueError(
            f"unscaled companion requested beyond first regular block: n={n}"
        )
    return c[n]
```

Therefore:

> **There is no code path that evaluates an unscaled rational/modular companion `c_n` with `n >= p`.**

The first-block companion is used in two places.

## 1.1 Seam-basis check

`assert_seam_bases` uses

```text
c_(p-1), c_(p-2)
```

together with `b_(p-1),b_(p-2)` to verify the unit-companion Casoratian basis:

```python
det_bc = (
    b[p - 1] * c[p - 2]
    - b[p - 2] * c[p - 1]
) % p
assert det_bc == 1 % p
```

Both indices are exactly in `[0,p-1]`.

This `det_bc` is the **basis determinant** and should not be confused with the later recorded charge determinant. `compute_record` discards this first value and keeps only the user-basis determinant from the helper.

## 1.2 Regular slope-7 companion charge

The script computes

```python
g7c = first_copy_gap_charge_mod(p, d7, c_first_block)
```

as a diagnostic/second entry of the regular slope-7 row.

Inside `first_copy_gap_charge_mod`, the sampled physical index is

```python
n = data.sigma + data.slope * t
```

and the forward differences use orders `R-1` and `R`, hence only `0 <= t <= R` is sampled.

For slope 7,

```text
R_7 = p-X_7,
sigma_7 + 7R_7 = p-1-r.
```

Therefore every physical companion index used by `g7c` satisfies

```text
sigma_7 <= n <= p-1-r < p.
```

So every actual slope-7 companion sample is also in the first block.

# 2. Does the final charge determinant actually use `g7c` or any unscaled companion value?

No.

The decisive code is

```python
# Regular slope-7 row: both basis solutions are p-integral.
g7b = first_copy_gap_charge_mod(p, d7, b_value)
g7c = first_copy_gap_charge_mod(p, d7, c_first_block)

# Distinguished finite slope-4 charge on b.
g4b_actual = first_copy_gap_charge_mod(p, d4, b_value)

# Associated-graded transverse slope-4 charge.
g4c = first_copy_gap_charge_mod(p, d4, p3c_first_seam)

# In columns (b,c), rows (7, desingularized 4), the lower-left entry is 0.
determinant_bc = g7b * g4c % p
```

Hence the recorded determinant is

```text
det_bc = charge7_kernel_b * charge4_transverse_p3c  (mod p).
```

The computed `g7c` does **not** enter `determinant_bc` at all. It is diagnostic information for the full row/basis picture.

Thus, after the seam-basis assertion has been made, the numerical value of the final `Record.det_bc` is obtained from:

```text
slope 7: ordinary Apéry b-values;
slope 4: desingularized p^3*c values, immediately replaced by low-block b-values.
```

In particular, the final determinant contains no literal `c_j`, `c_(p-1-r)`, or `c_(2p-1-r)` evaluation.

This is slightly stronger than the premise in the question: the scan does not merely keep its ordinary companion inside `[0,p-1]`; the final triangular determinant does not depend on the ordinary companion samples at all.

# 3. What exactly happens on slope 4?

This is where the answer is subtle.

The helper is

```python
def p3_companion_first_seam_mod(
    n: int, p: int, apery_block: list[int]
) -> int:
    """Return p^3*c_n mod p on the first singular block 0 <= n < 2p.

    For n<p, c_n is p-integral, hence p^3*c_n = 0 mod p.
    For n=p+q, Q3445's exact seam law gives p^3*c_(p+q)=b_q mod p.
    """
    assert 0 <= n < 2 * p
    if n < p:
        return 0
    return apery_block[n - p] % p
```

So the function being sampled is precisely the associated-graded piecewise function

```text
h_p(n) = 0,          0 <= n < p,
       = b_(n-p),    p <= n < 2p,
```

which represents

```text
p^3 c_n mod p.
```

The slope-4 charge is then

```python
g4c = first_copy_gap_charge_mod(p, d4, p3c_first_seam)
```

with

```text
R_4 = 2p-X_4,
sigma_4 + 4R_4 = 2p-1-r.
```

Consequently the sampled physical indices run from the lower slope-4 origin up through

```text
n_max = 2p-1-r.
```

For every genuine target, `r=p-1` is impossible because `b_(p-1) ≡ 1 (mod p)`. Hence `r <= p-2`, so

```text
n_max >= p+1.
```

Therefore the slope-4 associated-graded computation **definitely includes physical indices above `p`**.

At those samples write

```text
n = p+q.
```

The largest low-block index that appears is

```text
q_max = n_max-p = p-1-r < p.
```

Thus every high physical companion coordinate is replaced by an Apéry value in the safe range

```text
0 <= q <= p-1-r <= p-1.
```

So the correct answer to question 3 is:

> **Yes, the desingularization semantically introduces companion coordinates at indices `p+q > p`; no, it does not evaluate the rational companions there. It replaces them immediately by `b_q mod p`, with `q<p`.**

At the terminal slope-4 hit,

```text
n = sigma_4 + 4R_4 = 2p-1-r.
```

This is exactly the same shape as the reflected index in the literal slope-8 companion globalization. If the target zero is called `j` rather than `r`, it is

```text
u = 2p-1-j.
```

So the **semantic** high companion index from Q3527 has not disappeared from the geometry. What has changed is the representation.

```text
c_u
```

and then multiplied it by `(8p)^3`. That exposes denominator primes between `p` and `u`.

The scan instead keeps only its associated grade:

```text
p^3 c_u mod p = b_(u-p) mod p.
```

At the terminal point this is

```text
p^3 c_(2p-1-r)
    ≡ b_(p-1-r)                    (mod p).
```

No rational denominator survives this replacement.

This is why the primes `167` and `211` from Q3527 cannot appear in `det_bc`: the script never constructs `c_168` or `c_216` as rational numbers.

# 5. Does the scan therefore avoid the auxiliary-prime obstruction?

## Locally: yes

For the purpose actually performed by the scan — deciding whether the first associated-graded charge is zero modulo the target prime — the auxiliary-prime obstruction is completely bypassed.

The slope-4 transverse charge can be evaluated from the integer Apéry block

```text
b_0,...,b_(p-1)
```

with no denominator clearing at unrelated primes.

Thus one should **not** interpret a failure of literal integrality of

```text
(8p)^3 c_(2p-1-r)
```

as invalidating the `det_bc` scan. The scan computes a different object: the canonical first-seam associated grade.

## Globally: not yet

The scan does not construct one characteristic-zero object independent of `p`. Its low-block replacement is still explicitly target-prime dependent:

```text
h_p(n)=0                 for n<p,
h_p(n)=b_(n-p)           for p<=n<2p.
```

Likewise its slope-4 data depend on

```text
R_4 = 2p-X_4,
sigma_4,
X_4,
```

and the slope-7 data depend on `R_7=p-X_7`.

For a fixed global `m`, different candidate target primes use different shifts, different truncation orders, and different low-block Apéry indices. The script proves no characteristic-zero identity saying that all those target-specific residues are reductions of one common integer `E(m,H)`.

Therefore the `46/46` p-unit scan does **not by itself** give the requested global radical carrier.

# 6. A denominator-free characteristic-zero lift exists for each single target

There is nevertheless a useful positive consequence.

Because `first_copy_gap_charge_mod` uses ordinary forward differences, one can define a completely integral lift of the slope-4 associated-grade charge for a fixed target prime `p` without any companion at all.

Define the integer sequence

```text
H_p(n) = 0                         for n<p,
       = b_(n-p)                   for p<=n<2p.
```

Then set

```text
G4_ag(p,r,H)
 := U_(4,R4)
    [ R4 * Delta^(R4-1) H_p(sigma4+4t)|_(t=0)
      +(1-R4) * Delta^R4 H_p(sigma4+4t)|_(t=0) ].
```

Every coefficient here is an integer: `U_(4,R4)=binom(-X_4,R_4)` is integral and finite differences use integer binomial coefficients. Its reduction modulo `p` is exactly the script's

```text
charge4_transverse_p3c.
```

Similarly the slope-7 kernel charge already has an obvious integral lift using the ordinary Apéry sequence.

Hence for each target one can define

```text
E_p := G7_b(p,r,H) * G4_ag(p,r,H) in Z
```

with

```text
E_p mod p = det_bc.
```

This formulation has **zero auxiliary companion denominators**.

That is real progress. It shows that the Q3527 denominator problem is not intrinsic to the local Route-1 determinant.

But `E_p` is indexed by `p`; it is not yet the global `E` required by the radical argument.

# 7. Why the target-dependent integral lift is not automatically low height

There is a second obstruction even after denominator removal: the naive integral lift is long.

The orders of the forward differences are `R_7` and `R_4`, and on q=6 cells these are linear in `p` (hence linear in the global size parameter). The slope-4 low-block sequence reaches Apéry indices as large as

```text
p-1-r.
```

Thus a direct characteristic-zero expansion involves a linear-width binomial combination of Apéry numbers of linear index.

The project currently has no theorem that this particular integer combination has logarithmic height `o(n)`. There can be substantial cancellation, and the successful mod-`p` determinant suggests useful structure, but the scan itself only computes residues and does not certify such cancellation in characteristic zero.

So there are now two possible characteristic-zero lifts with different problems:

### Literal companion lift

```text
p^3 c_(p+q)
```

Problem: unrelated companion denominator primes; a safe uniform lcm-cubic clearing has logarithmic cost `Theta(p)=Theta(n)`.

### Associated-grade Apéry lift

```text
H_p(p+q)=b_q
```

Problem: no auxiliary denominators, but the lift is target-prime dependent and naively has linear-width/linear-height data. A prime-independent `o(n)` compression theorem is not yet proved.

The second route is clearly preferable for Route 1 because it has removed the known denominator obstruction completely.

# 8. Can the auxiliary denominators be cleared without linear height if one insists on the literal high companion?

No such theorem is presently available.

For a high index

```text
s=p+q,   0<=q<p,
```

the exact companion block law at an unrelated prime `ell` says

```text
ell^3 c_(ell+u) ≡ b_u (mod ell).
```

Whenever `s=ell+u<2ell` and `ell ∤ b_u`, this gives

```text
v_ell(c_s)=-3.
```

Hence a literal rational `c_s` may carry cubic poles at primes unrelated to the target `p`. The Q3527 fixtures `167` and `211` are exact examples.

A safe global clearing by `lcm(1,...,s)^3` has

```text
log lcm(1,...,s)^3 = 3s+o(s)=Theta(p),
```

which is linear height. The exact reduced denominator can be smaller through numerator cancellation, but no uniform `exp(o(n))` bound for it has been proved.

Therefore if the campaign returns to the literal high-index companion, the old obstruction remains.

The important point is that the current scan gives no reason to return to it.

# Final answers to the three explicit questions

## 1. Which companion evaluations `c_?` are used?

Actual unscaled companion evaluations:

```text
c_0,...,c_(p-1)
```

only. In particular:

- `c_(p-1),c_(p-2)` in the seam-basis assertion;
- `c_(sigma_7+7t)` for `0<=t<=R_7` in the diagnostic slope-7 companion charge, all ending at `p-1-r`.

The final charge determinant `Record.det_bc` does **not** use the slope-7 companion charge at all.

The slope-4 transverse column formally represents `p^3 c_n`, not `c_n`, and is computed through the seam-law surrogate.

## 2. Are any indices greater than `p-1`?

For **actual unscaled `c_n` evaluation:** no.

For the **formal desingularized coordinate `p^3 c_n`: yes.** Slope 4 samples physical indices through

```text
n=2p-1-r,
```

so it crosses `p` and uses formal coordinates `p^3c_(p+q)` with

```text
0<=q<=p-1-r<p.
```

## 3. Does `p^3 c_(p+q)=b_q mod p` introduce indices greater than `p`?

Yes semantically, but not computationally as rational companion evaluations.

The code substitutes

```text
p^3c_(p+q) -> b_q mod p
```

immediately. Therefore all data actually used to produce the residue are first-block integral Apéry data.

This **does avoid the Q3527 auxiliary-denominator obstruction for the scan itself**.

It does **not yet turn the local p-unit scan into the global theorem**, because the associated-grade surrogate is still `p`-dependent and the script supplies neither a common characteristic-zero integer nor an `o(n)` height bound.
