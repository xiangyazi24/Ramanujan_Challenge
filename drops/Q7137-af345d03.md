# Q7137 audit: resultant-gcd candidate scanner for fully-deflated triple roots

## 1. Safe candidate implication

Let

\[
F=N_a^\circ(x),\qquad G=N_b^\circ(x+a),\qquad J=N_c^\circ(x+a+b).
\]

Assume the already established structural exclusions: \(p\notin\mathfrak U_H\), and therefore the relevant leading coefficients do not vanish modulo \(p\). Suppose \(r\in\mathbf F_p\) is a common root of \(F,G,J\). Then

\[
F(r)=G(r)=0,
\]
so the Sylvester resultant specializes to
\[
\operatorname{Res}_x(F,G)\equiv0\pmod p.
\]
Likewise
\[
\operatorname{Res}_x(F,J)\equiv0\pmod p.
\]
Hence every surviving common root prime satisfies

\[
p\mid \gcd(R_{FG},R_{FJ}),
\]
where
\[
R_{FG}=\operatorname{Res}(F,G),\qquad R_{FJ}=\operatorname{Res}(F,J).
\]

This is only a candidate carrier. It is strictly weaker than pencil-content equality:

\[
p\mid\gcd(R_{FG},R_{FJ})
\]
may arise from an \(F,G\) root unrelated to the \(F,J\) root. Therefore the scanner must recompute the triple gcd over \(\mathbf F_p\).

The only qualification needed is the standard resultant implication:
if \(\operatorname{lc}(F)\not\equiv0\pmod p\) and \(\operatorname{lc}(G)\not\equiv0\pmod p\), then a common root implies vanishing of the resultant. Leading-coefficient-collapse primes are already handled by the structural carrier.

## 2. Scanner design

The algorithm is:

1. Generate triples \((a,b,c)\), \(a,b,c\ge2\), \(a+b+c\le H\).
2. Construct the fully deflated polynomials.
3. Compute

```python
Rfg = F.resultant(G)
Rfj = F.resultant(J)
carrier = gcd(Rfg, Rfj)
```

4. Remove structural factors supported on \(\mathfrak U_H\).
5. Factor the remaining integer.
6. Keep only primes

\[
p>s^2,
\]

where \(s=a+b+c\). Small primes cannot support a primitive four-zero chain because the total interval length is too large relative to the field size.

7. For every remaining prime:

```python
Fp.<x> = GF(p)[]
ff = F.change_ring(Fp)
gg = G.change_ring(Fp)
jj = J.change_ring(Fp)
D = gcd(ff, gcd(gg,jj))
```

8. Enumerate roots of \(D\). For each root \(r\):

- discard the centered reflection root;
- discard any root producing an intermediate return;
- test the original Apéry value:

\[
b_r\equiv0,\quad b_{r+a}\equiv0,\quad b_{r+a+b}\equiv0,\quad b_{r+a+b+c}\equiv0\pmod p.
\]

Only surviving roots are reported.

## 3. Sage implementation skeleton

```python
from sage.all import *


def candidate_primes(F,G,J, structural=1):
    rfg = ZZ(F.resultant(G))
    rfj = ZZ(F.resultant(J))
    C = gcd(rfg, rfj) // gcd(gcd(rfg, rfj), structural)
    return [p for p,e in factor(abs(C)) if p > 0]


def scan_triple(F,G,J,a,b,c):
    out=[]
    C = gcd(F.resultant(G), F.resultant(J))
    s=a+b+c
    for p,e in factor(abs(ZZ(C))):
        if p <= s*s:
            continue
        R=GF(p)['x']
        fp=R(F); gp=R(G); jp=R(J)
        d=gcd(fp,gcd(gp,jp))
        for r in d.roots(multiplicities=False):
            if is_center_root(r,a,b,c,p):
                continue
            if has_intermediate_return(r,a,b,c,p):
                continue
            if apery_chain(r,a,b,c,p):
                out.append((p,r))
    return out
```

The routines `is_center_root`, `has_intermediate_return`, and `apery_chain` must use the original recurrence data rather than resultant data.

## 4. Symmetry and caching

The scanner should cache:

- \(N_h^\circ\) by gap \(h\);
- translated polynomial hashes;
- integer resultants already computed for repeated pairs;
- factorizations of candidate carriers.

Use reflection symmetry

\[
N_h(x)\leftrightarrow N_h(-h-1-x)
\]

to identify equivalent gap triples. This reduces the search space roughly by the permutation/reflection orbit size.

The triple count through \(H=50\) is small enough for an exact Sage scan with memoization; the expensive operation is integer resultant computation, not finite-field verification.

## 5. Expected false positives

The gcd carrier is deliberately overinclusive. False positives arise from:

1. \(F,G\) sharing a root unrelated to \(F,J\);
2. \(F,J\) sharing a different root;
3. accidental common factors after reduction modulo a large prime.

Therefore:

\[
\gcd(R_{FG},R_{FJ})
\neq
\text{pencil content}
\]

and no equality claim is valid. The finite-field triple gcd is the deciding step.

A correct implementation should report the statistics:

- number of candidate primes from the gcd carrier;
- number surviving the finite-field gcd;
- number surviving center/intermediate filtering;
- number producing genuine four-zero chains.

The final output must be interpreted as a certificate search, not as a proof of the aligned-content hypothesis.
