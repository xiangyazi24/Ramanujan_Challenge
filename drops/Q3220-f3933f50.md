# Q3220 — cold audit of the candidate-sparse Cartier summation

## Verdict

The Brun--Titchmarsh improvement is **valid for the transverse two-extreme radical/incidence mass**, and the proposed cutoff

```text
R(M) = floor(sqrt(M)/log log M)
```

is safely inside the resulting `o(M)` range.

More precisely, if

```text
C_M(R) = {1 <= r <= R : r < M/2 and M-r is prime},
D_r(M) = gcd(G_r^minus(M), G_r^plus(M)),
```

then, uniformly for `3 <= R < M/2`,

```text
sum_{r in C_M(R)} log rad D_r(M)
    << R^2 log M / log R.                    (1)
```

The same bound therefore holds after restricting, for each candidate `r`, to the physically admissible outside primes `ell` satisfying

```text
ell > 3r,
r < (M mod ell) < ell,
```

and the two extreme necessary equations. Candidate multiplicity is handled correctly: if one `ell` occurs for several different `r`, it is counted once for each such `r`, exactly as in the original double sum.

For the proposed cutoff,

```text
R^2 log M / log R
  = (2+o(1)) M/(log log M)^2
  = o(M).                                     (2)
```

So the claimed improvement is real. In fact the theorem is stronger: any near-square-root cutoff `R=sqrt(M)/L(M)` with `L(M)->infinity` and `log L=o(log M)` works. Equivalently, the exact sufficient condition from this argument is

```text
R(M)^2 log M = o(M log R(M)).                 (3)
```

There is, however, one important scope correction.

The existing no-carry Cartier reduction, as stated, is a **mod-ell support statement**. It proves that a physical transverse prime `ell` divides `D_r(M)`. It does **not by itself** prove the prime-power comparison

```text
v_ell(full normalized packet content) <= v_ell(D_r(M)).
```

The factors `(r!)^4` and `Z_r` are harmless at such `ell`; the obstruction is not those factors but the fact that the passage from the physical extreme coordinate to `G_r^plus/minus(M)` is only known modulo `ell`, through the reduced label `x=M mod ell`. Thus (1)--(2) are unconditional for the radical/two-extreme incidence mass. To promote them to the full normalized-content contribution with prime powers, one needs either a separate bounded-exponent theorem in the relevant `ell`-range or a genuine prime-power lift of the extreme comparison.

This distinction matters. The repository records a banked global cap `v_p(G_n) <= 6` for `sqrt(n)<p<=n` in `problems/3.2/UNDERSTANDING.md`, but `ell>3r` alone does not force `ell>sqrt(M)` in the present small-`r` sector. Hence that cap can be used where its hypotheses apply, but it is not a formal substitute for a prime-power extreme lemma for every transverse `ell` considered here.

## 1. Uniform pointwise height, with an explicit absolute constant

The previously used bound `log D_r(M)=O(r log M)` is genuinely uniform over all q=1 candidates.

Let

```text
z_r = deg Z_r = ceil(r/2).
```

For `1 <= r < M/2`, all terms in `A_r^minus(M)` and `A_r^plus(M)` are nonnegative. Using only `binom(N,k) <= N^k`, one gets

```text
A_r^minus(M)
 <= (r+1) 4^r M^(3r).
```

Indeed

```text
binom(M,j) binom(M,r-j) <= M^r,
binom(2M-r+j,j)^2 <= (2M)^(2j) <= (2M)^(2r).
```

For the plus family,

```text
M+r-j < 3M/2,
```

so the same displayed `4^r M^(3r)` upper bound is valid (and is slightly wasteful).

Also

```text
Z_r(M)
 = product_{m=0}^{z_r-1} (M-m)
 >= (M-r/2)^z_r
 > (3M/4)^z_r,
```

because `r<M/2`. Therefore, for either sign,

```text
0 < G_r^sign(M)
 <= (r!)^4 (r+1) 4^r (4/3)^z_r M^(3r-z_r).
```

Since

```text
3r-z_r = floor(5r/2),
```

we have

```text
log D_r(M)
 <= log min(G_r^minus(M),G_r^plus(M))
 <= floor(5r/2) log M
    + 4 log(r!)
    + log(r+1)
    + r log 4
    + z_r log(4/3).                           (4)
```

For every admissible pair one has `M>=3` and `r<M`, so `log r <= log M`. From (4), for example,

```text
log D_r(M) <= 9 r log M                       (5)
```

is a valid uniform absolute bound. The numerical constant `9` is not important; what matters is that there is no hidden `M`- or `r`-dependent implied constant.

No resultant is used in (4)--(5).

## 2. Brun--Titchmarsh gives the candidate saving exactly as proposed

Put `H=floor(R)` and assume `3 <= H < M/2`. Candidate remainders `r<=H` correspond injectively to primes

```text
p = M-r in [M-H, M-1].
```

Hence

```text
# C_M(H)
 = pi(M-1) - pi(M-H-1).                       (6)
```

The ordinary `q=1` Brun--Titchmarsh inequality gives, uniformly in the location of the interval,

```text
pi(x+y)-pi(x) <= 2y/log y                     (7)
```

for the present range `y=H>1` (or one may replace `2` by any absolute Brun--Titchmarsh constant and absorb the finitely many tiny cases). Taking

```text
x=M-H-1,
y=H,
```

in (7) yields

```text
# C_M(H) <= 2H/log H.                         (8)
```

There is no endpoint problem: the interval in (6) is exactly the one produced by `1<=r<=H`. If one uses a version of Brun--Titchmarsh with slightly different open/closed endpoints, at most one endpoint prime changes and contributes `O(H)`, which is harmless.

Now simply use `r<=H`:

```text
sum_{r in C_M(H)} r
 <= H #C_M(H)
 <= 2H^2/log H.                               (9)
```

Combining (5) and (9),

```text
sum_{r in C_M(H)} log D_r(M)
 <= 9 log M sum_{r in C_M(H)} r
 <= 18 H^2 log M / log H.                    (10)
```

Since `log rad D_r(M) <= log D_r(M)`, (10) proves (1) with an explicit absolute constant.

A dyadic decomposition in `r` gives the same order of magnitude; it is not needed. The crude inequality `r<=H` already captures the full Brun--Titchmarsh gain.

## 3. The proposed cutoff and the actual threshold

Take

```text
H = floor(sqrt(M)/log log M).
```

For sufficiently large `M`, `H>=3` and `H<M/2`. Also

```text
log H
 = (1/2) log M - log log log M + o(1)
 = (1/2+o(1)) log M.
```

Therefore (10) gives

```text
sum_{r in C_M(H)} log rad D_r(M)
 <= (36+o(1)) M/(log log M)^2
 = o(M).                                      (11)
```

So the proposed cutoff is correct.

The natural theorem-level formulation is more general. If `R=R(M)` satisfies

```text
R -> infinity,
R < M/2,
R^2 log M / log R = o(M),                    (12)
```

then the candidate-sparse two-extreme radical mass up to `R` is `o(M)`.

In particular, if

```text
R = sqrt(M)/L(M),
L(M) -> infinity,
log L(M) = o(log M),
```

then

```text
log R = (1/2+o(1)) log M
```

and (10) becomes

```text
O(M/L(M)^2) = o(M).                           (13)
```

Thus `log log M` is not special. The method reaches any `o(sqrt(M))` cutoff whose logarithm is still asymptotic to `(1/2)log M`.

### Correction to the older threshold wording

Without candidate sparsity, summing (5) over every `1<=r<=R` gives

```text
O(R^2 log M).
```

Consequently the exact scale

```text
R = sqrt(M/log M)
```

only gives `O(M)`, not `o(M)`. The unconditional no-sparsity condition is really

```text
R = o(sqrt(M/log M)),
```

with, for example, `R=sqrt(M)/log M` as a concrete safe choice.

With Brun--Titchmarsh the threshold improves to essentially

```text
R = o(sqrt M),
```

and the proposed `sqrt(M)/log log M` is a valid explicit choice.

## 4. Cross-candidate multiplicity is not lost

Define the transverse two-extreme prime set for a candidate `r` by

```text
P_ext(M,r) = {
  ell prime :
    ell > 3r,
    r < (M mod ell) < ell,
    ell | G_r^minus(M),
    ell | G_r^plus(M)
}.
```

Then

```text
product_{ell in P_ext(M,r)} ell | rad D_r(M),
```

so

```text
sum_{ell in P_ext(M,r)} log ell
 <= log rad D_r(M).                           (14)
```

Summing (14) over candidate `r` gives

```text
sum_{r in C_M(H)} sum_{ell in P_ext(M,r)} log ell
 <= sum_{r in C_M(H)} log rad D_r(M).         (15)
```

If the same prime `ell` belongs to `P_ext(M,r)` for `k` different candidates, then the left side of (15) contains `k log ell`, while the right side also contains at least one `log ell` from each of those `k` different gcds. Thus the argument preserves the relevant **cross-candidate multiplicity** exactly. It never collapses to a distinct-prime union.

Equivalently, with

```text
mu_{M,H}(ell)
 = #{r in C_M(H) : ell in P_ext(M,r)},
```

(15) says

```text
sum_ell mu_{M,H}(ell) log ell
 << H^2 log M/log H.                          (16)
```

This is the clean multiplicity form of the theorem.

## 5. Why the factorial and boundary erasures are safe for transverse support

Let

```text
x = M mod ell,
```

with the least residue chosen so that

```text
ell > 3r,
r < x < ell.
```

The erasure factors are then `ell`-adic units.

### The factorial

Since `ell>3r>r`,

```text
ell does not divide r!,
```

hence `(r!)^4` is an `ell`-unit.

### The boundary factor `Z_r`

Every root erased by

```text
Z_r(X) = product_{m=0}^{floor((r-1)/2)} (X-m)
```

lies at `m<r`. Since `x>r`, each factor `x-m` lies strictly between `0` and `ell`; therefore

```text
Z_r(x) != 0 mod ell.                          (17)
```

Because `M==x mod ell`, (17) also gives

```text
Z_r(M) != 0 mod ell.
```

Thus the exact integral erasure

```text
G_r^sign(X) = (r!)^4 A_r^sign(X)/Z_r(X)
```

neither creates nor destroys an `ell`-zero in this transverse branch.

### Root-label evaluation

Since `G_r^sign` has integer coefficients,

```text
G_r^sign(M) == G_r^sign(x) mod ell.           (18)
```

Hence the stated no-carry physical implication

```text
physical extreme sign vanishes mod ell
  => G_r^sign(x) == 0 mod ell
```

immediately gives

```text
ell | G_r^sign(M).
```

Doing this for both signs gives `ell|D_r(M)`.

### Candidate prime versus outside prime

There is also no hidden collision with the q=1 candidate prime `p=M-r`. If `ell=p`, then

```text
M mod ell = r,
```

which violates the strict transverse condition `r<x`. Thus the branch automatically has `ell!=p`.

### Primitive-content warning

The theorem should be stated using the exact integral `G_r^minus,G_r^plus` for which the no-carry equivalence was proved. If a verifier additionally replaces `G_r^sign` by a primitive polynomial obtained by dividing out a constant integer content, that scalar must be retained unless it is separately proved to be an `ell`-unit for every `ell>3r` under consideration. Primitive normalization is not formally innocuous merely because it is convenient for a resultant computation.

For the `G_r` as defined above, no such extra scalar division occurs, so there is no issue.

## 6. Full 21-packet support is bounded by the two extreme gcd

Let a **physical full-packet prime** mean a prime `ell` for which all normalized packet equations hold at the candidate `(M,r)`. In particular, the two physically saturated extreme coordinates vanish.

Therefore, in the transverse no-carry branch,

```text
full 21-packet prime
  => both extreme equations
  => ell | D_r(M).                            (19)
```

Thus (10)--(16) remain valid if `P_ext(M,r)` is replaced by the smaller set of primes satisfying **all** 21 packet equations.

This is only a one-way implication. A prime divisor of `D_r(M)` may fail one or more of the other 19 equations. Such false positives are harmless for an upper bound.

So the candidate-sparse theorem is enough for the **support/radical mass of the full packet** in this branch.

## 7. But higher `ell`-adic multiplicity is not supplied by the mod-`ell` Cartier comparison

This is the only substantive failure in the stronger proposed interpretation.

The available chain is

```text
physical extreme coordinate == 0 mod ell
  <=> G_r^sign(x) == 0 mod ell
  <=> G_r^sign(M) == 0 mod ell.               (20)
```

Equation (20) is a first-residue statement. It does not imply, for `e>=2`,

```text
physical extreme coordinate == 0 mod ell^e
  => G_r^sign(M) == 0 mod ell^e.              (21)
```

The reason is simple: `x` records only `M mod ell`, not `M mod ell^e`, and the Cartier/Lucas reduction being used is only modulo `ell`. The fact that `(r!)^4` and `Z_r(x)` are `ell`-units removes denominator/boundary concerns, but it does not manufacture a prime-power lift of the Lucas reduction.

Abstractly, two integers may agree modulo `ell` while having different positive `ell`-adic valuations. Thus support equivalence is insufficient to compare exact valuations.

Consequently the implication

```text
v_ell(full normalized packet content)
 <= v_ell(D_r(M))                              (22)
```

is **not established from the stated Cartier-boundary formulas alone**.

To make (22) theorem-level, one needs one of the following additional inputs.

### Prime-power extreme lift

Prove that for every `e>=1` in the transverse branch,

```text
ell^e | normalized full packet
  => ell^e | G_r^minus(M)
     and ell^e | G_r^plus(M).                 (23)
```

Then (22) follows immediately.

A weaker sufficient version would be

```text
v_ell(full packet content)
 <= C0 + C1 v_ell(D_r(M))                     (24)
```

with absolute constants and with the additive term separately summable.

### Independent bounded exponent

Alternatively, if in the exact prime range under consideration one already knows

```text
v_ell(full normalized content) <= C            (25)
```

with an absolute constant, then the radical estimate (16) implies the full content estimate up to the factor `C`.

The repository state does record such a cap `v_p(G_n)<=6` for the global gcd in the range `sqrt(n)<p<=n` (`problems/3.2/UNDERSTANDING.md`). But `ell>3r` does not itself imply `ell>sqrt(M)` here, so one must check the range before invoking that cap. The current Cartier packet audit also explicitly works with mod-`p` packet congruences; it should not be read as a hidden mod-`p^e` theorem.

Thus the correct unconditional conclusion of this audit is radical/support-level unless an independent exponent input is attached.

## 8. The theorem-ready statement

### Theorem (candidate-sparse transverse Cartier radical bound)

There is an absolute constant `C` such that the following holds. Let `M>=3` and let `R` satisfy

```text
3 <= R < M/2.
```

For each integer `r` with

```text
1 <= r <= R,
M-r prime,
```

let

```text
D_r(M)=gcd(G_r^minus(M),G_r^plus(M)).
```

Let `P(M,r)` be any set of primes satisfying

```text
ell > 3r,
r < (M mod ell) < ell,
ell | G_r^minus(M),
ell | G_r^plus(M).
```

Then

```text
sum_{1<=r<=R, M-r prime}
    sum_{ell in P(M,r)} log ell
 <= C R^2 log M/log R.                        (26)
```

The same conclusion holds if `P(M,r)` is the set of transverse no-carry primes satisfying all 21 normalized packet equations, because those primes satisfy the two extreme necessary equations.

In multiplicity notation,

```text
mu_{M,R}(ell)
 = #{r<=R : M-r prime and ell in P(M,r)},
```

one has

```text
sum_ell mu_{M,R}(ell) log ell
 <= C R^2 log M/log R.                        (27)
```

Hence, for every `R=R(M)` with

```text
R^2 log M/(M log R) -> 0,
```

the left side of (26)--(27) is `o(M)`. In particular,

```text
R=floor(sqrt(M)/log log M)
```

gives

```text
sum_ell mu_{M,R}(ell) log ell
 = O(M/(log log M)^2)
 = o(M).                                      (28)
```

### Scope clause

The theorem controls the **radical/incidence mass**: one `log ell` for each candidate-prime incidence `(r,ell)`. It does not assert (without an additional prime-power lemma) that the exact `ell`-adic valuation of the full normalized packet content is at most `v_ell(D_r(M))`.

## 9. Verifier-ready checklist

A verifier of the exact theorem should distinguish support from exponent assertions.

For each test `M,R`:

```text
1. candidates = [r : 1<=r<=R, r<M/2, is_prime(M-r)]
2. assert len(candidates) <= 2R/log R       # up to endpoint convention
3. assert sum(candidates) <= 2R^2/log R
4. for r in candidates:
       D = gcd(abs(Gminus(r,M)), abs(Gplus(r,M)))
       assert log(D) <= 9*r*log(M)
5. for every claimed physical transverse ell:
       x = M % ell
       assert ell > 3*r
       assert r < x < ell
       assert gcd(ell, factorial(r)) == 1
       assert Z_r(x) % ell != 0
       assert Gminus(r,M) % ell == 0
       assert Gplus(r,M) % ell == 0
       count[ell] += 1
6. mass = sum(count[ell]*log(ell) for ell)
   assert mass <= sum(log(rad(D_r(M))) for candidate r)
```

The verifier must **not** include

```text
v_ell(full_packet) <= v_ell(D_r(M))
```

as an asserted theorem unless it separately verifies or imports a mod-`ell^e`/valuation comparison.

Likewise, if a primitive polynomial `q_r^sign=G_r^sign/c_r^sign` is used computationally, the verifier must either retain `c_r^sign` in the carrier or prove that every transverse `ell>3r` is coprime to that content.

## 10. Final audit conclusions

1. **Brun--Titchmarsh step: confirmed.** Candidate remainders `r<=R` are in bijection with primes in a length-`R` interval immediately below `M`, and uniformly
   ```text
   sum_{r<=R, M-r prime} r << R^2/log R.
   ```

2. **Uniform height: confirmed.** The exact formula gives an absolute bound such as
   ```text
   log D_r(M) <= 9 r log M.
   ```

3. **Proposed cutoff: confirmed.** With `R=sqrt(M)/log log M`, the transverse two-extreme/full-packet support mass is
   ```text
   O(M/(log log M)^2)=o(M).
   ```

4. **Stronger range:** the argument works whenever
   ```text
   R^2 log M=o(M log R),
   ```
   in particular for `R=sqrt(M)/L(M)` with any slowly diverging `L` satisfying `log L=o(log M)`.

5. **Cross-candidate multiplicity: correctly retained.** Repeated occurrence of the same `ell` for several candidates is counted several times on both sides of the estimate.

6. **Factorial and boundary factors: harmless for transverse support.** `ell>3r` makes `r!` an `ell`-unit, and `r<M mod ell` puts the label strictly above every zero of `Z_r`.

7. **Full 21-packet support: controlled.** Every full physical packet prime satisfies the two extreme necessary equations, so its radical incidence is included in the bound.

8. **Prime-power/full-content valuation comparison: not supplied by this argument.** The current reduction is modulo `ell`; no mod-`ell^e` lift follows merely from the unit erasures. A separate exponent cap or prime-power extreme theorem is required if the desired conclusion counts `v_ell` rather than support.

9. **Older cutoff wording needs care.** `R=sqrt(M/log M)` is only the `O(M)` threshold for the unsieved sum; to get `o(M)` without candidate sparsity one needs a little-o below that scale. Brun--Titchmarsh moves the corresponding threshold to a little-o below `sqrt M`.

So there is no failure in the proposed candidate-sparse summation itself. The exact theorem gained is a genuine near-square-root `o(M)` result for the transverse Cartier **radical/incidence** sector. The remaining caveat is sharply localized to prime-power multiplicity, not to Brun--Titchmarsh, endpoint handling, or the factorial/boundary erasure.
