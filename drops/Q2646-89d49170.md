# P3.2 cold audit: proposed three-integer large-prime equivalence

## Verdict

The caller-local markdown `Q32_PADE_THREE_INTEGER_LARGE_PRIME_EQUIVALENCE.md` is not present on any connector-visible repository branch, so I cannot honestly do a textual line-by-line audit of that uncommitted file. I therefore checked the claims named in the question against the current GitHub-visible canonical fixed-slice implementation and redid the boundary algebra from scratch.

The result is **mixed, with two necessary corrections**.

1. The fixed-slice truncated Newton/Lucas congruence is sound when the cutoff is the repository cutoff
   \[
   H=\left\lfloor\frac{n-q}{2q+1}\right\rfloor,
   \qquad K=H+1.
   \]
   The direct/reflected split must use **inclusive** midpoint inequalities. At the midpoint the two descriptions coincide; they are alternatives, not two additive contributions.

2. The natural `F_minus = T(-1)` is indeed a nonzero integer. There is a short unconditional sign proof; no candidate prime or nonvanishing modulo a candidate prime is needed.

3. A uniform claim that the factorial carrier has `v_p=1` is **false**. At the central fixed-slice prime one gets exactly two first-digit carries:
   \[
   v_p\!\left(\binom nK\binom{n+K}K\right)=2.
   \]
   This happens on an infinite boundary family. The correct large-prime formula is
   \[
   1+\mathbf 1_{\,2n+1=(2q+1)p}.
   \]

4. More seriously, the **unrestricted radical of the three integers is not a fixed-slice radical**. The committed proofs always condition on `floor(n/p)=q`, and that condition is essential. A concrete large-prime counterexample is `q=1,n=27,p=11`: the natural q=1 three-integer package is divisible by 11, but `floor(27/11)=2`, not 1. Thus any exact equivalence must use a slice-restricted radical such as `rad_{floor(n/p)=q}`.

5. The `O(n/T)` omitted-prime tail is correct **for radicals**. The exact threshold is naturally `p <= n/(T+1)`, and Chebyshev's theta bound gives `O(n/T)`. It does not by itself control prime powers in an unrestricted gcd.

6. After the slice restriction and the central-square correction, the two-limit argument is valid. No uniformity in fixed `q` is needed because one first fixes `T`, takes `n -> infinity` over finitely many odd slices, and only then sends `T -> infinity`.

So the proposed result can be repaired into a correct **radical equivalence**, but not into an unrestricted equality of the three-integer gcd with a fixed-slice radical, and not with a universal one-carry exponent-one statement.

# 1. Canonical cutoff and the residue boundary

Fix a positive odd quotient `q` and write

\[
d=2q+1,
\qquad
n=qp+r,
\qquad 0\le r<p,
\]

for a prime in the `q`-slice. Define the repository cutoff

\[
H=\left\lfloor\frac{n-q}{d}\right\rfloor,
\qquad K=H+1.
\tag{1}
\]

For floor-sensitive manipulations the safe residue convention is

\[
n-q=dH+t,
\qquad 0\le t<d.
\tag{2}
\]

Do **not** simultaneously allow `t=d` while keeping the same `H`. If one uses a convention `1 <= t <= d`, then the endpoint `t=d` must be renormalized by

\[
(H,t=d)\longmapsto(H+1,t=0).
\tag{3}
\]

Otherwise the boundary carrier index is off by one.

A concrete failure is

\[
q=1,\quad n=10,\quad d=3.
\]

Since `n-q=9`, the canonical representation is

\[
H=3,\ t=0,\ K=4.
\]

If one instead writes `9=3*2+3` and incorrectly keeps `H=2`, one uses the wrong boundary `K=3`. For the fixed-slice prime `p=7`,

\[
\binom{10}{3}=120\not\equiv0\pmod7,
\qquad
\binom{13}{3}=286\not\equiv0\pmod7,
\]

so the wrong boundary misses the prime completely. With the correct `K=4`,

\[
\binom{10}{4}=210\equiv0\pmod7,
\qquad
\binom{14}{4}=1001\equiv0\pmod7.
\]

This is not a cosmetic endpoint convention: it changes the prime support.

## `H+1` itself never reaches `p` in the fixed slice

There is also a useful correction to the phrase “when `H+1` crosses a base-`p` digit.” With `H` defined by (1), that crossing cannot occur for a genuine fixed-slice prime. Indeed

\[
\frac{n-q}{d}
\le
\frac{(q+1)p-q-1}{2q+1}
<p-1,
\]

because

\[
(2q+1)(p-1)-((q+1)p-q-1)=q(p-1)>0.
\]

Hence

\[
\boxed{K=H+1\le p-1.}
\tag{4}
\]

So `K` is always one base-`p` digit. The real first-digit boundary is whether **`r+K` reaches `p`**, and equality matters.

# 2. Exact direct/reflected thresholds

Put

\[
B^-_{q,n}=\binom nK,
\qquad
B^+_{q,n}=\binom{n+K}K.
\tag{5}
\]

Since `K<p`, divisibility by `p` is determined at the first base-`p` digit.

For the direct factor,

\[
p\mid B^-_{q,n}
\iff r<K
\iff r\le H.
\]

Using (1),

\[
r\le H
\iff
(2q+1)r\le qp+r-q
\iff
2qr\le q(p-1),
\]

hence

\[
\boxed{
p\mid B^-_{q,n}
\iff 2r\le p-1.
}
\tag{6}
\]

For the reflected factor,

\[
p\mid B^+_{q,n}
\iff r+K\ge p.
\]

Since `K=H+1`, this is `H >= p-r-1`. Substituting (1) gives

\[
\boxed{
p\mid B^+_{q,n}
\iff 2r\ge p-1.
}
\tag{7}
\]

Thus every fixed-slice prime occurs in at least one factor. At

\[
r=\frac{p-1}{2}
\tag{8}
\]

**both** factors contain `p`.

The direct/reflected Newton-Lucas formulas must therefore be partitioned as, for example,

```text
direct:    2r <= p-1,
reflected: 2r >  p-1,
```

or with the equality assigned the other way. Using strict inequalities on both sides loses the midpoint. Counting the midpoint twice in the transformed value is also wrong: the two branch descriptions agree there because

\[
r=p-1-r.
\]

# 3. The `t=0` / midpoint identity

With the canonical residue (2),

\[
2n+1=d(2H+1)+2t.
\tag{9}
\]

Because `d` is odd,

\[
d\mid(2n+1)
\iff t=0.
\tag{10}
\]

If the quotient

\[
p_c=\frac{2n+1}{d}
\]

is prime, then at `t=0`

\[
p_c=2H+1,
\qquad
r=H=\frac{p_c-1}{2}.
\tag{11}
\]

So the residue boundary `t=0` is exactly the possible midpoint prime. This is the boundary that must not be discarded when `n-q` is divisible by `2q+1`.

It occurs on an infinite algebraic family: for any odd prime `p`, set

\[
H=\frac{p-1}{2},
\qquad
n=q+(2q+1)H
   =\frac{(2q+1)p-1}{2}.
\tag{12}
\]

Then `floor(n/p)=q`, `t=0`, and `r=(p-1)/2`.

# 4. Exact carrier valuation: the one-carry statement needs a square exception

For arbitrary `p`, because `K<p`, Legendre gives the exact all-digit formulas

\[
\boxed{
 v_p\binom nK
 =\sum_{\nu\ge1}
   \mathbf 1_{\,n\bmod p^\nu<K},
}
\tag{13}
\]

and

\[
\boxed{
 v_p\binom{n+K}K
 =\sum_{\nu\ge1}
   \mathbf 1_{\,n\bmod p^\nu\ge p^\nu-K}.
}
\tag{14}
\]

These formulas are the safest way to state the result when higher base-`p` digits are allowed.

For the large fixed-slice regime, `p>q+1` implies

\[
n+K<(q+2)p\le p^2,
\]

so every term with `nu>=2` vanishes. Combining (6) and (7) then yields

\[
\boxed{
 v_p(B^-_{q,n}B^+_{q,n})
 =1+\mathbf 1_{\,2r+1=p}
 =1+\mathbf 1_{\,2n+1=(2q+1)p}.
}
\tag{15}
\]

Equivalently, with (2), the extra valuation occurs exactly for the prime `p=2H+1` when `t=0`.

### Concrete counterexample to `v_p=1`

Take

\[
q=1,\quad n=10,\quad H=3,\quad K=4,\quad p=7,\quad r=3.
\]

Then

\[
v_7\binom{10}{4}=1,
\qquad
v_7\binom{14}{4}=1,
\]

so

\[
\boxed{
v_7(B^-B^+)=2.
}
\]

This is exactly the `2*n+1 == (2*q+1)*p` branch already asserted in `q32_fixed_q_certificates.py`.

### Why a genuine large-prime hypothesis is still needed for exponent one/two

If `p>q+1` is dropped, higher powers can cross. For example

\[
q=9,\quad p=3,\quad n=27,\quad H=0,\quad K=1.
\]

Then

\[
B^-B^+=\binom{27}{1}\binom{28}{1}=27\cdot28,
\]

so

\[
v_3(B^-B^+)=3,
\]

not 1. Formulas (13)-(14), not the one-carry slogan, are the exact general statement.

For radical support this exponent issue is harmless; for an equality of integer gcds or a normalized `B/p mod p` argument it is not harmless. At the midpoint the product must be normalized by `p^2`, not by `p`.

# 5. Truncated Newton/Lucas transform and the midpoint

The visible fixed-q content code uses the generalized Legendre-Euler/Newton transform with cutoff `H`. Its coefficientwise fixed-slice congruence is

\[
T_{n,q}(c)
\equiv
b_j Q_q(c^p)\pmod p,
\qquad
j=\min(r,p-1-r),
\tag{16}
\]

where

\[
Q_q(z)=\sum_{a=0}^q
\binom qa\binom{q+a}{a}z^a
=P_q(1+2z).
\tag{17}
\]

The cutoff is exactly large enough because

\[
2r\le p-1 \Longrightarrow j=r\le H,
\]

and

\[
2r\ge p-1 \Longrightarrow j=p-1-r\le H.
\]

At the midpoint `t=0`, `p=2H+1`, one has `j=H`, so the last retained Newton term is genuinely needed. The correct formula is still simply

\[
\boxed{
T_{n,q}(c)\equiv b_H Q_q(c^p)\pmod p.
}
\tag{18}
\]

There is no factor of two. The direct and reflected derivations are the same congruence at the common boundary.

Thus any proof that changes `<=H` to `<H`, or uses strict direct/reflected inequalities and omits the common point, has a real endpoint gap.

# 6. `F_minus` is a clean selector, and it is genuinely nonzero

For the natural specializations

\[
F_-(n,q)=T_{n,q}(-1),
\qquad
F_+(n,q)=T_{n,q}(1),
\tag{19}
\]

(16)-(17) give, for odd candidate `p`,

\[
Q_q(-1)=P_q(-1)=(-1)^q,
\]

so

\[
\boxed{
F_-(n,q)\equiv(-1)^q b_j\pmod p.
}
\tag{20}
\]

For the P3.2 fixed slices `q` is odd, hence this is just

\[
F_-\equiv-b_j\pmod p.
\]

This is the clean congruence: there is no fixed exceptional factor.

For `F_+`,

\[
\boxed{
F_+(n,q)\equiv P_q(3)b_j\pmod p.
}
\tag{21}
\]

Therefore `F_+` by itself is not an exact selector at primes dividing the fixed integer `P_q(3)`. For instance

\[
P_3(3)=63,
\]

so at `q=3,p=7,n=21,r=0`, one has `b_0=1` but

\[
F_+\equiv0\pmod7.
\]

The simultaneous use of `F_-` removes this finite-q nuisance. A statement `p|F_+ iff p|b_j` must either assume `p not | P_q(3)` or include `F_-`.

## Unconditional integer nonvanishing of `F_-`

The conclusion `F_- != 0` is provable without finding any candidate prime.

Write

\[
L_{n,m}=\binom nm\binom{n+m}m,
\qquad
f_i=\sum_a\binom ia^3>0,
\]

and

\[
S_m=\sum_{i=0}^m\binom mi f_i>0.
\]

The transform in `q32_legendre_content.py` is

\[
T(c)=\sum_{m=0}^H [y^m]Q_n(c+y)
       \sum_{i=0}^m\binom mi(-c)^{m-i}f_i.
\]

Because

\[
Q_n(z)=P_n(1+2z),
\]

Legendre parity gives

\[
Q_n(-1+y)=(-1)^nQ_n(-y),
\]

and hence

\[
[y^m]Q_n(-1+y)=(-1)^{n+m}L_{n,m}.
\]

Thus

\[
F_-=(-1)^n\sum_{m=0}^H(-1)^m a_m,
\qquad
a_m=L_{n,m}S_m.
\tag{22}
\]

Now `H <= (n-1)/3`. Moreover `S_{m+1}>S_m`, and

\[
\frac{L_{n,m+1}}{L_{n,m}}
=\frac{(n-m)(n+m+1)}{(m+1)^2}>1
\qquad (m<H).
\]

Hence

\[
0<a_0<a_1<\cdots<a_H.
\]

Pairing consecutive terms in the alternating sum proves

\[
\boxed{
\operatorname{sgn}(F_-)=(-1)^{n+H},
\qquad F_-\ne0.
}
\tag{23}
\]

This proof survives every residue boundary, including `t=0`. If the proposed markdown instead proves nonvanishing by choosing a candidate prime with `b_j != 0 mod p`, that argument is unnecessary and is not logically safe: the candidate set may be empty, and one cannot assume a good candidate before proving it exists. Formula (23) is the clean replacement.

# 7. The three integers do not isolate the quotient slice without an explicit prime restriction

This is the most important structural correction.

The visible scripts prove statements of the form

```text
for p with floor(n/p) == q:
    p divides the certificate  <=>  p divides b_j.
```

They do **not** prove that every other large prime is absent from the same integers.

Define the natural boundary carrier

\[
C_q(n)=B^-_{q,n}B^+_{q,n}.
\tag{24}
\]

Then for a prime in the q-slice, (6)-(7) and (20) imply

\[
p\mid\gcd(C_q(n),F_-(n,q))
\iff p\mid b_j.
\tag{25}
\]

Adding `F_+` does not change this implication. But (25) is a **conditional-on-the-slice** statement.

## Large cross-slice counterexample: `q=1,n=27,p=11`

Take the q=1 package. Its cutoff is

\[
H=\left\lfloor\frac{27-1}{3}\right\rfloor=8,
\qquad K=9.
\]

Now take `p=11`. Then

\[
\left\lfloor\frac{27}{11}\right\rfloor=2,
\qquad r=5,
\qquad j=5.
\]

So `p=11` is **not** in the q=1 slice. Nevertheless

\[
b_5=819005=11\cdot74455,
\]

and `j=5 <= H < p`. The same Lucas/Newton truncation therefore gives

\[
T_{27,8}(c)\equiv b_5Q_2(c^{11})\equiv0\pmod{11},
\]

so

\[
11\mid F_-,
\qquad
11\mid F_+.
\]

The carrier also contains 11 on both sides:

\[
r=5<K=9,
\qquad
r+K=14\ge11,
\]

hence

\[
11\mid\binom{27}{9},
\qquad
11\mid\binom{36}{9}.
\]

Therefore 11 divides the natural q=1 three-integer gcd even though it lies in quotient slice 2.

This is not a tiny-prime phenomenon: `11 > sqrt(27)`. It shows that the integer package itself does not encode the quotient label.

Accordingly, the exact fixed-slice radical must be written as

\[
\boxed{
R_q(n)
=\operatorname{rad}_{\lfloor n/p\rfloor=q}
 \gcd\bigl(C_q(n),F_-(n,q),F_+(n,q)\bigr),
}
\tag{26}
\]

or equivalently with `F_+` omitted because `F_-` already has unit multiplier.

An unrestricted formula

\[
\operatorname{rad}\gcd(C_q,F_-,F_+)=R_q(n)
\]

is false in general.

This slice restriction is also necessary for the later two-limit argument. Cross-slice pollution can live at primes of order `n`, so it is not automatically swallowed by the `O(n/T)` small-prime tail.

# 8. Exact form of the `O(n/T)` tail

Let

\[
\mathcal P_q(n)=\{p\text{ prime}:\lfloor n/p\rfloor=q\},
\]

and for the relevant odd slices define

\[
R_q(n)
=\prod_{\substack{p\in\mathcal P_q(n)\\p\mid b_{n-qp}}}p,
\tag{27}
\]

with the reflected formulation giving the same zero condition by Apéry reflection.

If `q>T`, then

\[
\left\lfloor\frac np\right\rfloor>T
\Longrightarrow
p\le\frac{n}{T+1}.
\]

Therefore the entire omitted radical is bounded by the full primorial below `n/(T+1)`:

\[
0\le
\sum_{q>T}\log R_q(n)
\le
\vartheta\!\left(\frac{n}{T+1}\right),
\tag{28}
\]

where

\[
\vartheta(x)=\sum_{p\le x}\log p.
\]

Chebyshev's bound `theta(x)=O(x)` gives

\[
\boxed{
\sum_{q>T}\log R_q(n)=O\!\left(\frac nT\right).
}
\tag{29}
\]

This is fully uniform enough for the iterated-limit argument.

Two caveats are essential:

* The exact floor threshold is naturally `n/(T+1)`, not `n/T`. Replacing it by `n/T` is harmless asymptotically but loses the exact partition boundary.
* (29) is a **radical** bound. It does not imply
  \[
  \sum_{p\le n/(T+1)}v_p(M_n)\log p=O(n/T)
  \]
  for an arbitrary three-integer gcd `M_n`; extra exponent control would be needed.

# 9. Correct two-limit equivalence

Let `R(n)` denote the radical whose large-prime support is the union of the relevant odd quotient slices, with the fixed finite exceptional primes separated as in the existing P3.2 reductions. For an integer `T>=1`, put

\[
R_{\le T}(n)=
\prod_{\substack{1\le q\le T\\q\text{ odd}}}R_q(n).
\]

Then (28) gives

\[
0\le
\log R(n)-\log R_{\le T}(n)
\le
\vartheta\!\left(\frac{n}{T+1}\right)+O(1).
\tag{30}
\]

Consequently, if

\[
L=\limsup_{n\to\infty}\frac{\log R(n)}n,
\]

and

\[
L_T=\limsup_{n\to\infty}
\frac1n
\sum_{\substack{q\le T\\q\text{ odd}}}
\log R_q(n),
\]

then

\[
L_T\le L\le L_T+\frac{C}{T+1},
\]

hence

\[
\boxed{
L=\lim_{T\to\infty}L_T.
}
\tag{31}
\]

In particular,

\[
\boxed{
\frac{\log R(n)}n\to0
\iff
\text{for every fixed odd }q,
\quad
\frac{\log R_q(n)}n\to0.
}
\tag{32}
\]

The forward implication is immediate from `R_q(n) | R(n)`. For the reverse implication, fix `T`; there are only finitely many odd `q<=T`, so their normalized logs tend to zero. Equation (30) then gives

\[
\limsup_{n\to\infty}\frac{\log R(n)}n
\le\frac{C}{T+1},
\]

and finally `T -> infinity`.

No uniform estimate in fixed `q` is required. What **is** required is that `R_q` be the actual slice-restricted radical. Replacing it by the unrestricted radical of the three integers invalidates the exact decomposition behind (30), as the `q=1,n=27,p=11` example shows.

Also, unless existence of an ordinary limit has been proved independently, `limsup` is the technically correct formulation. Since all normalized logarithms are nonnegative, `limsup=0` is equivalent to convergence to zero.

# 10. Minimal exact corrections to the proposed theorem

A statement that survives the audit is the following.

Let `q` be fixed odd, set

\[
H=\left\lfloor\frac{n-q}{2q+1}\right\rfloor,
\quad K=H+1,
\quad
C_q(n)=\binom nK\binom{n+K}K,
\]

and let `F_-=T_{n,q}(-1)`, `F_+=T_{n,q}(1)`. For a prime `p` with

\[
\lfloor n/p\rfloor=q
\]

and `p>q+1`, put `r=n-qp` and `j=min(r,p-1-r)`. Then

\[
F_-\equiv(-1)^q b_j\pmod p,
\qquad
F_+\equiv P_q(3)b_j\pmod p,
\]

and

\[
v_p(C_q(n))
=1+\mathbf1_{2r+1=p}.
\]

Therefore

\[
\boxed{
 p\mid b_j
 \iff
 p\mid\gcd(C_q(n),F_-(n,q),F_+(n,q)),
 \qquad p\in\mathcal P_q(n).
}
\tag{33}
\]

Equivalently,

\[
\boxed{
R_q(n)
=\operatorname{rad}_{\mathcal P_q(n)}
  \gcd(C_q(n),F_-,F_+).
}
\tag{34}
\]

At the midpoint the carrier has exponent two, but (34) is unchanged because it is a radical statement.

The global radical then satisfies the tail estimate (30) and the iterated equivalence (31)-(32).

# 11. Exact verifier for the boundary counterexamples

The following standard-library script is self-contained. It verifies the carrier formulas, the `t=d` off-by-one example, the higher-digit failure when the large-prime hypothesis is dropped, and the large cross-slice pollution example. It reproduces the visible Legendre-Euler coefficient formula with an explicit cutoff.

```python
from math import comb


def vp(x, p):
    e = 0
    while x and x % p == 0:
        x //= p
        e += 1
    return e


def franel(m):
    return sum(comb(m, a)**3 for a in range(m + 1))


def trunc_coeff(n, H):
    f = [franel(i) for i in range(H + 1)]
    C = [sum(comb(n,k)*comb(n+k,k)*f[k]
             for k in range(H+1))] + [0]*n
    for degree in range(1, n+1):
        lo = max(0, H + 1 - degree)
        hi = min(H, n - degree)
        C[degree] = sum(
            (-1)**(H-i)
            * comb(n, i+degree)
            * comb(n+i+degree, i+degree)
            * comb(i+degree, i)
            * comb(degree-1, H-i)
            * f[i]
            for i in range(lo, hi+1)
        )
    return C


def peval(C, x):
    out = 0
    for c in reversed(C):
        out = out*x + c
    return out


def apery(N):
    b = [1, 5]
    for n in range(1, N):
        num = (34*n**3 + 51*n**2 + 27*n + 5)*b[n] - n**3*b[n-1]
        den = (n+1)**3
        assert num % den == 0
        b.append(num//den)
    return b[:N+1]

# 1. Correct q=1 midpoint: n-q = 3*3 + 0.
q, n, p = 1, 10, 7
H = (n-q)//(2*q+1)
K = H+1
assert (H, K) == (3, 4)
assert n//p == q
assert vp(comb(n,K), p) == 1
assert vp(comb(n+K,K), p) == 1
assert vp(comb(n,K)*comb(n+K,K), p) == 2
assert 2*n + 1 == (2*q+1)*p

# Wrong noncanonical representation n-q = 3*2 + 3 gives K=3
# and misses p=7 altogether.
K_wrong = 3
assert comb(10,K_wrong) % 7 != 0
assert comb(10+K_wrong,K_wrong) % 7 != 0

# 2. Higher p-adic digits if p>q+1 is dropped.
q, n, p = 9, 27, 3
H = (n-q)//(2*q+1)
K = H+1
assert (H, K) == (0, 1)
assert n//p == q
assert vp(comb(n,K)*comb(n+K,K), p) == 3
```
