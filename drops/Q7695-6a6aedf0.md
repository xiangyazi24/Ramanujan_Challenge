# 1. Exact arithmetic reduction

Write

\[
P(n)=34n^3+51n^2+27n+5,
\qquad
D(t)=1-34t+t^2.
\]

The Apéry recurrence is

\[
(n+1)^3b_{n+1}=P(n)b_n-n^3b_{n-1},
\qquad b_0=1,\quad b_1=5.
\]

For a fixed prime `p` and `n+1<p`, `(n+1)^3` is a unit modulo `p`; hence

\[
\boxed{
 b_{n+1}\equiv
 (P(n)b_n-n^3b_{n-1})(n+1)^{-3}\pmod p.}
\]

So `b_0,...,b_{p-1}` are obtained in `O(p)` machine-word operations after a linear inverse table.

The scanner first performs this cheap pass.  A common pair requires `b_r=0 mod p`; primes having no Apéry zero need no `g` computation at all.

## The algebraic square-root factor

Put

\[
Q(t)=D(t)^{-1/2}=\sum_{n\ge0}q_nt^n.
\]

Differentiating gives

\[
2D Q'+D'Q=0.
\]

The coefficient of `t^n` yields the exact recurrence

\[
\boxed{
(n+1)q_{n+1}=(34n+17)q_n-nq_{n-1},}
\qquad q_0=1,\quad q_1=17.
\]

Thus the `Q` prefix is also linear-time modulo `p`.

There is no denominator issue hidden here: by the Legendre generating function,

\[
Q(t)=\sum_{n\ge0}P_n(17)t^n
\]

and

\[
q_n=P_n(17)=
\sum_{k=0}^n
\binom nk\binom{n+k}{k}8^k\in\mathbb Z.
\]

Since `F(0)=1`, its formal reciprocal also has integer coefficients.  Therefore

\[
g(t)=F(t)^{-2}Q(t)
\]

has integral coefficients, and reduction of the characteristic-zero definition modulo `p` is exactly the computation in `F_p[[t]]`.

# 2. Fast exact computation of `g`

I do **not** assume that `g` is P-recursive.

For a prime with Apéry zeros, let

\[
L=1+\max\{r<p:b_r\equiv0\pmod p\}.
\]

Only `Xi_r` at those zero positions matters, so no coefficient at index `>=L` is needed.  The C++ worker forms the truncated `F,Q` and calls FLINT:

```text
Finv  = inverse_series(F, L)
Finv2 = mullow(Finv, Finv, L)
g     = mullow(Finv2, Q, L)
```

concretely via

```cpp
nmod_poly_inv_series(...)
nmod_poly_mullow(...)
nmod_poly_mullow(...)
```

Because formal-series coefficients below degree `L` depend only on input coefficients below degree `L`, this truncation is exact.

Then

\[
\Xi_0=-1,
\qquad
\Xi_r-\Xi_{r-1}=-5g_rb_{r-1},
\]

so a final linear pass computes the required `Xi` residues, testing them only when `b_r=0`.

This replaces characteristic-zero coefficient growth, repeated large gcds, and factorization by independent word-prime jobs plus quasi-linear FLINT series arithmetic.

# 3. D-finiteness check

The Apéry generating function is D-finite.  With

\[
\theta=t\frac d{dt},
\]

its Picard--Fuchs operator is

\[
\boxed{
\theta^3
-t(2\theta+1)(17\theta^2+17\theta+5)
+t^2(\theta+1)^3.}
\]

Equivalently,

\[
D\theta^3F
+(-51t+3t^2)\theta^2F
+(-27t+3t^2)\theta F
+(-5t+t^2)F=0.
\]

But D-finite series are not closed under reciprocals.  Hence the fact that `F` is D-finite does **not** imply that `1/F`, `1/F^2`, or

\[
g=1/(F^2\sqrt D)
\]

is D-finite.  In particular, I do not infer a linear P-recurrence for `g` from the Picard--Fuchs equation.

There is nevertheless a proved nonlinear differential-algebraic relation.  Define

\[
u=\frac{\theta F}{F}.
\]

Then

\[
\frac{\theta^2F}{F}=\theta u+u^2,
\qquad
\frac{\theta^3F}{F}=\theta^2u+3u\theta u+u^3,
\]

and division of the Picard--Fuchs equation by `F` gives

\[
\boxed{
D(\theta^2u+3u\theta u+u^3)
+(-51t+3t^2)(\theta u+u^2)
+(-27t+3t^2)u
+(-5t+t^2)=0.}
\]

On the other hand,

\[
\frac{\theta g}{g}
=-2u-\frac12\frac{\theta D}{D},
\]

so

\[
\boxed{
 u=-\frac12\frac{\theta g}{g}
   -\frac14\frac{\theta D}{D}.}
\]

Substitution and clearing powers of `gD` produces a polynomial nonlinear differential equation for `g`.  This proves differential algebraicity, but not D-finiteness; the scanner therefore sticks to the safer fast-series route.

# 5. Exact multiplicities

The modular `p` scan identifies support.  For each actual hit, the Sage verifier independently recomputes through the hit index modulo `p^e`.

Because every hit satisfies `r<p`, all recurrence denominators remain units modulo every `p^e`.  The verifier starts with a small exponent and doubles `e` until the residue of both `b_r` and `Xi_r` is nonzero.  Once a residue is nonzero modulo `p^e`, its valuation `<e` is the true characteristic-zero `p`-adic valuation.

\[

\]

Thus

\[
v_p(\gcd(b_r,\Xi_r))=1

for each observed common pair.

# 7. Complexity and memory

For each active prime define

\[
L_p=1+\max\{r<p:b_r\equiv0\pmod p\}.
\]

If `M_p(n)` denotes the FLINT cost of a length-`n` polynomial multiplication over `F_p`, the work at one prime is

```text
inverse table + Apéry row + zero scan: O(p)
Q recurrence:                           O(L_p)
F^-1 and truncated products:            ~ O(M_p(L_p))
Xi pass:                                O(L_p)
```

and the series phase is omitted entirely when there is no Apéry zero.

Hence the total cost through prime ceiling `P` is

\[
O\!\left(
\sum_{p\le P}p
+
\sum_{\substack{p\le P\\p\text{ active}}}M_p(L_p)
\right)
\]

up to the logarithmic Newton-series factor.  With quasi-linear polynomial multiplication, this is roughly quadratic in `P` up to logarithmic factors.

At `P=100000`, the unavoidable Apéry recurrence work is exactly

\[
\sum_{p\le100000}p=454396537
\]

coefficient steps.

Memory is `O(p)` words per worker.  The persistent data are the modular inverse table, Apéry row, `Q` prefix, and a constant number of FLINT polynomials, plus FLINT multiplication workspace.  At `p=100000` the explicit arrays themselves are only a few megabytes per process.  There is no characteristic-zero table of rapidly growing coefficients.

The prime jobs share no mutable arithmetic state, so process-level parallelism is essentially communication-free.

# 8. Crash-safe resumability

A completed prime is recorded as one JSON file such as

```text
p_000017.json
p_002237.json
...
```

containing

```text
algorithm version
p
r_limit
number of Apéry zeros
actual truncation length
common r values
elapsed seconds
```

The C++ worker writes `p_XXXXXX.json.tmp`, flushes it, and renames only after the whole prime has completed.  On restart:

- a valid final checkpoint skips the prime;
- a partial `.tmp` file is ignored;
- a missing prime is re-run;
- no two workers receive the same prime.

Thus an interruption loses at most one current prime per worker rather than a global scan state.  The Sage summarizer also checks the algorithm-version tag before accepting a checkpoint.

# 9. Why the prime triangle is the better test here

A characteristic-zero run through `r=100000` would require very large integers, repeated large gcds, and factorization/CRT reconstruction.  For the support-barrier question, direct prime scanning is more targeted.

For every prime `p<=100000`, we inspect every `r<p`.  In particular, any hypothetical counterexample satisfying

\[
p>5r
\]

with `p<=100000` automatically has `r<p`, so it lies inside the scanned triangle.  No factorization is needed: the exact decision is simply

\[
b_r\equiv0\pmod p,
\qquad
\Xi_r\equiv0\pmod p.
\]

This also records all `p>r` common pairs, rather than only barrier violations.

> For every prime `p<=100000` and every integer `1<=r<p`, simultaneous
> `p|b_r` and `p|Xi_r` occurs exactly at `(17,13)` and `(2237,492)`.

\[
