# R2A certificate route audit

## Verdict

A finite certificate route is possible in principle, and it is the correct next target. It is not the same as PSLQ: the certificate must prove that the endpoint extended Bloch elements are equal to torsion (or that their difference has a specified torsion order) inside the extended pre-Bloch group.

The existing general Suslin–Zickert–Merkurjev–Suslin input can be replaced by an explicit finite certificate of one of the following forms:

1. an extended Bloch group torsion certificate
2. an explicit lifted five-term relation certificate
3. a certified flattening identity reducing the Rogers sum to rational multiples of pi^2

The first concrete computation should be: compute the exact extended Bloch element for the four endpoint shapes and search for a bounded-order relation `N*xi = 0` in the extended pre-Bloch presentation.

## Required certificate data

For each endpoint alpha/beta the certificate should contain:

```
K = number field containing all shapes and flattenings
z_j in K, j=T,U,V,W
(p_j,q_j) flattening integers
epsilon_j orientation signs
xi = sum epsilon_j [z_j;p_j,q_j]
```

plus a finite proof object:

```
N * xi = sum_i c_i * FiveTerm_i + parity_corrections
```

where every FiveTerm_i is an explicit lifted five-term relation in the extended pre-Bloch group.

A machine checker only needs:

- exact arithmetic in K
- verification that every relation is a valid lifted five-term relation
- verification of flattening edge/parity conditions
- verification that the resulting element is zero

This is fundamentally different from PSLQ. PSLQ only guesses a relation among evaluated transcendental numbers.

## Algorithm from the endpoint data

### Step 1: construct exact shapes

Use the existing chart:

```
u=(L+X^3)/(X(L+X))
r=-(1+sqrt(1+4*u^2))/(2*u)
T=1-r^2
U=u
V=u/X
W=1/(1-uX)
```

Represent each shape exactly in the endpoint number field.

### Step 2: compute the extended Bloch element

Build

```
xi = Σ epsilon_j [z_j;p_j,q_j]
```

with the Neumann flattening constraints:

- edge log sums vanish
- parity sums vanish
- filling log constraint vanishes

The filling correction must either be included explicitly or absorbed into filling-adapted flattenings.

### Step 3: reduce in the extended pre-Bloch group

Search for an integer N such that

```
N*xi = 0
```

using the lifted five-term presentation.

Practical approaches:

- compute in the Z-module generated by the finite set of conjugates of the shapes
- use exact linear algebra over the relation lattice generated by five-term moves
- use known torsion generators of `K_3^ind(K)` only as a bound, not as the proof

### Step 4: extract the Rogers value

The extended Rogers regulator satisfies

```
R([z;p,q]) = Rogers(z;p,q) mod pi^2 Z
```

and torsion gives

```
R(xi) in pi^2 Q.
```

The explicit certificate gives the denominator from the exhibited order N, rather than from a generic w_2 bound.

## Existing scripts: expected role

The current scripts are useful but do not replace the certificate.

Likely reusable:

- `shape_pairing.py`: needed to identify the correct epsilon signs and companion-shape transformations.
- `shapes300.sage`: useful for high precision exploration and embedding tests.
- `pin.sage`: useful for exact endpoint field normalization.

The terminal failure mode to avoid is:

```
PSLQ found rational combination of evaluated Rogers values
```

This is evidence only. It is not a proof object.

## Denominator implication

If the certificate proves

```
N xi = 0
```

then

```
N R(xi) = 0 mod pi^2 Z
```

so

```
R(xi)=k*pi^2/N
```

for an integer k modulo N.

A certified interval evaluation then identifies k uniquely.

This is stronger than using Merkurjev–Suslin:

```
K_3^ind(K)_tors -> denominator bound
```

because it proves the actual order of the specific class.

The key Lean theorem should not formalize dilogarithm analysis first. It should formalize the finite certificate:

```
certificate : N * xi = 0
```

Then the analytic regulator theorem can be applied as an interface theorem.

## First computation to run

Do this before any large five-term search:

1. Run `shape_pairing.py` and freeze the exact correspondence

```
chart shape -> SnapPy tetrahedron -> companion transform -> epsilon
```

2. Build the exact four-term extended Bloch element.

3. Reduce its conjugates modulo the five-term relation lattice.

4. Ask for the smallest N <= generic torsion bound satisfying

```
N*xi == 0
```

If this succeeds, the rational reconstruction becomes a consequence of an explicit certificate instead of a numerical guess.

The current bottleneck is therefore not the dilogarithm evaluation. It is producing and checking the finite relation certificate.
