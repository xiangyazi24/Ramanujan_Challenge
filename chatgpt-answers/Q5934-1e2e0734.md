# Ramanujan Challenge assistant help

`--help` displays the recommended request format for repository-scoped mathematical and formalization work.

## Usage

```text
[PROJECT CONTEXT]
project: Ramanujan_Challenge
project repo: https://github.com/xiangyazi24/Ramanujan_Challenge.git

TASK:
State the exact theorem, audit, computation, proof repair, or implementation you need.

SOURCE STATE:
Give a commit SHA, branch, file paths, section numbers, theorem names, or script names.

REQUIREMENTS:
Specify exactness, acceptable assumptions, proof-versus-evidence boundaries,
required checker language, and any forbidden approaches.

DELIVERY:
Specify GitHub, Notion, or direct-chat delivery and the required destination.
```

## Supported work

```text
exact-algebra     Symbolic identities, elimination, recurrences, Smith forms,
                  Kummer/Lucas valuations, finite differences, resultants.

audit             Hostile review of a proof, claimed lemma, script, numerical
                  certificate, or asymptotic reduction.

checker           Reproducible Sage, Python, SymPy, PARI/GP, or Lean-oriented
                  verification code, with theorem/evidence/open-step separation.

repo-analysis      Read a specified commit and trace definitions, dependencies,
                  current status, regressions, or discrepancies among notes/scripts.

lean               Formalization design, statement audit, proof decomposition,
                  and API-sensitive code when the requested Mathlib version is known.

counterexample     Search for the smallest exact failure of a proposed universal
                  statement and identify the missing hypothesis.

certificate        Produce multiplication-back, divisibility, rank, determinant,
                  or finite-range certificates suitable for independent replay.
```

## Useful request options

These are descriptive request fields, not literal command-line switches:

```text
--commit SHA              Read this exact repository state.
--files PATH...           Restrict attention to named files.
--sections RANGE...       Restrict attention to named note sections or line ranges.
--exact                   No statistical fit or heuristic substitution.
--hostile                 Act as an adversarial referee.
--prove-or-counterexample Do not assume the claim; prove it or find a failure.
--checker sage|python|lean|sympy
--no-guess                Do not invoke guessed recurrences or uncertified APIs.
--ascii-formulas          Put load-bearing formulas in fenced text blocks.
--deliver github|notion|chat
```

## Strong request example

```text
Read commit 55a92ba, Q32_SEPARATION_ANALYSIS.md Section 68.17, and
q32_operator_syzygy_audit.sage. For each prime p dividing Q_I, derive the
mod-p normal form of the six quotient columns. Either prove that one explicit
2x2 minor is a p-unit under the stated safe hypotheses, or give the smallest
counterexample and the missing hypothesis. Include a Sage multiplication-back
checker. Distinguish theorem, finite audit, and open step.
```

## Output conventions

A rigorous response should normally separate:

```text
PROVED       Identities established symbolically or by a certified theorem.
FINITE AUDIT Exact computations over a stated finite range.
COUNTERMODEL A failure in a larger abstract category, clearly distinguished
             from a failure of the actual Apéry/Laurent-shell specialization.
OPEN STEP    The precise lemma still needed.
```

When a repository claim cannot be established from the supplied hypotheses, the response should not promote numerical evidence to a theorem. It should instead state the exact local criterion, exhibit a counterexample when available, and supply a checker that can test the distinguished repository specialization.
