# Verdict

The shortest Lean-realistic proof is not to search for a weight-three primitive of the target kernel alone. Use the elementary product

```plain text
F(x) = log(1+x) * Li2(1-x).
```

For 0 < x < 1,

```plain text
(d/dx) Li2(1-x) = log(x)/(1-x),
```

so

```plain text
F'(x)
 = Li2(1-x)/(1+x)
   + log(x)*log(1+x)/(1-x).                       (1)
```

Moreover,

```plain text
F(0) = log(1)*Li2(1) = 0,
F(1) = log(2)*Li2(0) = 0.                         (2)
```

Therefore FTC on the closed interval gives

```plain text
0 = integral_0^1 F'(x) dx
  = J + integral_0^1 Li2(1-x)/(1+x) dx.           (3)
```

The affine reflection t = 1-x gives, with no additional sign,

```plain text
integral_0^1 Li2(1-x)/(1+x) dx
 = integral_0^1 Li2(t)/(2-t) dt.                  (4)
```

The existing theorem radialWeightThreeIntegral26 is precisely the remaining evaluation, in the natural normalization

```plain text
integral_0^1 Li2(t)/(2-t) dt
 = (pi^2/4)*log(2) - zeta(3).                     (5)
```

Combining (3)--(5),

```plain text
J = zeta(3) - (pi^2/4)*log(2).
```

This uses no double series and no rearrangement at all.

# Sign and endpoint audit

The chain-rule sign is the only easy place to make a mistake. Since

```plain text
Li2'(y) = -log(1-y)/y,
y = 1-x,
y' = -1,
```

we get

```plain text
(d/dx) Li2(1-x)
 = (-log(x)/(1-x))*(-1)
 = log(x)/(1-x),
```

not its negative.

The substitution sign is also correct. In oriented interval-integral notation,

```plain text
integral_comp_sub_left:
  integral_a^b f(d-x) dx = integral_(d-b)^(d-a) f(x) dx.
```

With d=1, a=0, and b=1, the transformed bounds are again 0..1; the reversal of the ordinary bounds has already canceled the derivative -1.

As a numerical/sign sanity check, on 0 < x < 1 the target integrand is negative, while

```plain text
Li2(x)/(2-x) > 0.
```

Thus (3) must read J = -radialIntegral. This forces the radial theorem's right side to be

```plain text
(pi^2/4)*log(2) - zeta(3),
```

and the target right side to be its negative.

There are no delicate boundary products. The exact one-sided limits are simply

```plain text
lim_(x -> 0+) log(1+x)*Li2(1-x) = 0,
lim_(x -> 1-) log(1+x)*Li2(1-x) = 0,
```

because the product extends continuously to [0,1], with the exact values in (2).

# Why the direct FTC certificate is better than the canned integration-by-parts theorem

Mathlib 4.29 has the exact integration-by-parts theorem

```javascript
intervalIntegral.integral_mul_deriv_eq_deriv_mul_of_hasDerivAt
```

but applying it directly with

```plain text
u(x) = log(1+x),
v(x) = Li2(1-x)
```

requires separate proofs that both derivative functions are interval integrable. In particular, it asks for

```plain text
IntervalIntegrable (fun x => log(x)/(1-x)) volume 0 1,
```

which is true but is an unnecessary extra lemma.

Instead use

```javascript
intervalIntegral.integral_eq_sub_of_hasDerivAt_of_le
```

on the product F itself. It only asks that the combined derivative in (1) be interval integrable. That side condition is immediate from:

1. the target-kernel IntervalIntegrable lemma already established in Problem24Euler.lean as part of the series-to-integral bridge; and

1. continuity of x |-> Li2(1-x)/(1+x) on [0,1].

This is the shortest formal architecture.

have hFTC :

# What is not needed

The proof does not need:

- a new trilogarithm primitive;

- dilog26_half or trilog26_half;

- alternatingWeightThreeIntegral26;

- logSquareOnePlusIntegral26;

- Fubini/Tonelli for a double series;

- any grouped or conditionally convergent rearrangement;

- an improper-integral limit at either endpoint.

The minimal reusable inputs are:

```plain text
1. Li2'(x) = -log(1-x)/x on 0<x<1;
2. Li2 continuous on [0,1] and Li2(0)=0;
3. target-kernel interval integrability from Problem24Euler;
4. radialWeightThreeIntegral26;
5. the exact Mathlib FTC and affine-substitution lemmas above.
```
