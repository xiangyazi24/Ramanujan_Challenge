# Q5829 — Concrete numerical-certification plan for endpoint regulator/integral value

## 1. Scope and certification target

The goal is a replayable Lean certificate for the final endpoint regulator value in Ramanujan Challenge Problem 3.1. The certificate should not ask Lean to discover numerical facts. Instead, all transcendental evaluations should be reduced to finite rational inequalities whose proofs are kernel-checked.

The final pipeline should have four layers:

1. exact algebraic reduction of the regulator integral to a finite expression in logs, dilogarithms, and powers of π;

1. interval evaluation of every transcendental atom;

1. rational interval arithmetic proving the final enclosure;

1. a final exact comparison showing the target rational value lies inside the enclosure.

No native_decide, no axioms, and no floating-point trust boundary are needed.

## 2. Current Lean audit target

The first audit item is Certify.lean and the Dilog modules under the Problem 3.1 Lean development.

The required check is whether Certify.lean proves only the generic interval lemmas or actually evaluates the concrete endpoint parameters. The expected separation is:

- generic lemmas: interval arithmetic, monotonicity, series remainder bounds;

- concrete certificate: endpoint substitutions, explicit rational constants, final inequality.

If the current file only instantiates abstract lemmas but does not contain the concrete endpoint values, add a separate certificate layer rather than expanding the generic theorem.

## 3. Exact expression inventory

The certificate should expose the following finite list of transcendental atoms:

- log(q_i) for positive rational/algebraic endpoint quantities q_i;

- Li₂(z_i) for rational/algebraic arguments in the admissible convergence range;

- π².

Every occurrence must be normalized before interval evaluation. In particular:

- combine products of logs algebraically first;

- use dilogarithm identities only when they reduce the number of atoms;

- keep signs explicit to prevent orientation errors.

The main independent recomputation checks are:

1. evaluate the regulator orientation numerically from the original integral formula;

1. evaluate the reduced dilogarithm expression;

1. compare both signs and normalization constants.

The two values must agree before formal certification.

## 4. Rational log certificate

For a positive rational number x, reduce using

x = 2^a 3^b ... y

where y is close to 1. Then

log(x) = a log(2)+b log(3)+...+log(y).

For |t|<1, use

log(1+t)=Σ_{k=1}^N (-1)^(k+1)t^k/k + R_N

with

|R_N| <= |t|^(N+1)/((N+1)(1-|t|)).

All partial sums are rational. The remainder is represented by a rational interval.

Recommended parameters:

- force |t| <= 1/2 by range reduction;

- use N=80–120 for 100-bit final accuracy;

- certificate size per logarithm: roughly a few KB.

## 5. Rational dilogarithm certificate

For |z|<=1/2, use

Li₂(z)=Σ_{k=1}^N z^k/k² + R_N.

The tail satisfies

|R_N| <= |z|^(N+1)/((N+1)^2(1-|z|)).

For arguments outside this interval use standard transformations:

- Li₂(z)+Li₂(-z)=1/2 Li₂(z²);

- inversion/reflection identities when applicable;

- transform to an argument with absolute value at most one half.

Recommended parameters:

- N=100–200 for each transformed dilogarithm;

- keep all coefficients rational;

- store numerator/denominator bounds rather than decimals.

Expected certificate size:

- fewer than 20 dilog atoms: below a few hundred KB;

- suitable for direct Lean replay.

## 6. π certificate

Use the existing Mathlib π infrastructure where possible. For a self-contained certificate, use an arctangent Machin-style identity:

π/4 = 4 atan(1/5) - atan(1/239).

For

atan(x)=Σ (-1)^k x^(2k+1)/(2k+1),

alternating-series bounds give exact rational intervals.

The tails are bounded by the first omitted term.

Suggested truncation:

- atan(1/5): 40–50 terms;

- atan(1/239): 15–20 terms.

This gives far more precision than needed for the regulator comparison.

## 7. Final interval arithmetic certificate

The final theorem should have the shape:

```javascript
theorem regulator_certified :
  regulator_value ∈ [L,U] ∧ target ∈ [L,U] := by
  ...
```

where L,U are explicit rationals.

Recommended margin:

- compute all transcendental atoms to at least 80 decimal digits;

- leave a final enclosure width below 10^-50;

- compare against the target rational with a gap much larger than the interval width.

## 8. Failure modes to catch

Before formal replay, run three independent checks:

### Sign check

Reverse the path orientation numerically and verify the regulator changes sign.

### Normalization check

Compare the raw integral and the Bloch/dilog reduced formula before applying the final factor.

### Endpoint check

Evaluate each endpoint contribution separately; accidental cancellation should not hide an incorrect endpoint branch.

The final replay proof should be deterministic and fast because the expensive work is performed when generating rational certificates, not by Lean search.
